WAG1 — ANONİM İSTEK SİSTEMİ KURULUMU

Bu sürüm GitHub Pages ön yüzünü Supabase Auth + Postgres ile bağlamak için hazırlandı.
Supabase, istekleri veritabanında tutar; admin paneli ise parola ile oturum açar.

1) Supabase'te yeni bir proje oluştur.
2) supabase.sql dosyasında ADMIN_EMAIL yazan yeri yönetici hesabının e-postasıyla değiştir, sonra Dashboard > SQL Editor içinde dosyanın tamamını çalıştır.
3) Authentication > Providers / Email ayarlarında email + password girişini açık tut.
4) Authentication ayarlarında yeni kullanıcıların kendi kendine kayıt olmasını (self-signup) kapat.
5) Authentication > Users bölümünden yalnızca yönetici hesabını oluştur. Bu hesap admin panelinde kullanılacak.
6) Supabase Dashboard > Project Settings > API Keys bölümünden Project URL ve Publishable key değerlerini al.
7) supabase-config.js içindeki iki placeholder değeri bunlarla değiştir.
   ÖNEMLİ: service_role veya başka bir secret key'i tarayıcıya koyma.
8) index.html ve tüm site dosyalarını GitHub Pages sitenin ana dizinine yükle.
9) Admin paneli şu adreste olur:
   https://KULLANICI.github.io/REPO/admin/
10) Yönetici e-posta + şifreyle giriş yaptıktan sonra anonim istekleri görür, yeniler ve silebilir.

GİZLİLİK
- Formda isim veya e-posta alanı yoktur.
- Veritabanına class_name, message ve created_at kaydedilir.
- Ancak hosting/veritabanı sağlayıcısının teknik logları olabilir; sistem için "internette hiçbir teknik iz kalmaz" garantisi verilmez.

GÜVENLİK
- GitHub Pages'e Supabase Publishable key koymak normaldir; asıl güvenlik veritabanındaki RLS politikaları ve Auth ile sağlanır.
- Service role/secret key'i GitHub'a koymak güvenli değildir.
- Auth self-signup kapalı kalmalıdır; aksi halde authenticated olarak başka kullanıcılar da admin sorgusuna erişebilir.
